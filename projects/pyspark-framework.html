Data Engineering Framework

Python PySpark Databricks Azure Snowflake Delta Lake

A production-grade PySpark / Databricks data engineering framework covering multi-source ingestion, Informatica-style transformations, regression testing, and Unity Catalog write-back.

View on GitHub ↗

Overview

This framework was built for a production Databricks environment to standardise how data pipelines are written across a team. Rather than each pipeline being ad-hoc, the framework provides a library of reusable functions that cover the full lifecycle: connect → read → transform → test → write.

The codebase (~4,600 lines) has been sanitised for public use — all client-specific names, credentials, and server addresses have been replaced with generic placeholders.

Key Capabilities

Multi-Source Ingestion

  • On-Prem JDBC — SQL Server and Oracle via configurable connection profiles
  • Azure Blob Storage — CSV, JSON, text, and Delta formats
  • Snowflake — Read/write via the Spark-Snowflake connector with RSA key auth
  • Salesforce — Bulk and standard API insert, update, and upsert via simple-salesforce
  • REST APIs — Paginated fetch with OAuth2 token refresh

Transformation Utilities

A set of Informatica-inspired transformation functions that mirror the patterns used in visual ETL tools:

  • infa_router — splits a DataFrame into multiple based on filter conditions
  • infa_joiner — wraps Spark join with sensible defaults
  • md5_checksum — generates MD5 hashes across a column list for change detection
  • generate_insert_update_delete_flags — SCD-style IUD flag generation from a joined staging/target DataFrame
  • lookup_dataframe — left join lookup with configurable return columns

Regression Testing

  • compare_schemas — validates column names and types between two DataFrames
  • hash_comp — row-level MD5 comparison to detect data drift
  • compare_dataframes — cell-by-cell diff with mismatch reporting
  • check_for_special_characters — flags columns containing unexpected characters

Write-Back Patterns

  • Delta Lake merge (upsert) with generated WHEN MATCHED / WHEN NOT MATCHED conditions
  • Table swap (overwrite via rename) for full-reload patterns
  • Databricks Unity Catalog schema-qualified writes
  • Snowflake stored proc execution

Code Sample

Generating SCD-style IUD flags from a joined staging and target DataFrame:


# Join staging data with current target
df_joined = infa_joiner(
    left_df=df_stage,
    right_df=df_target,
    join_type="left",
    join_keys=["customer_id"]
)

# Generate Insert / Update / Delete flags
flag_dict = {
    "insert_flag":  "customer_id_right IS NULL",
    "update_flag":  "customer_id_right IS NOT NULL AND md5_stage != md5_target",
    "delete_flag":  "active_right = 0"
}
df_flagged = generate_insert_update_delete_flags(df_joined, flag_dict)

# Split into separate DataFrames per operation
result = generate_insert_update_delete_dataframes(df_flagged, {
    "insert": "insert_flag = 1",
    "update": "update_flag = 1",
    "delete": "delete_flag = 1"
})
df_inserts = result["insert"]
df_updates = result["update"]

Local Testing

The pure utility functions (global utils, Informatica transformations, regression testing) can be run locally with PySpark without any cloud credentials. A Jupyter notebook (python/test_framework_local.ipynb) in the repo demonstrates all functions end-to-end.
