Overview

A lot of SQL practice resources stop at GROUP BY. This suite goes further — the problems are modelled on the kind of queries that actually come up in data engineering and analytics work: handling hierarchies, building slowly changing dimension patterns, and writing queries that are readable and performant at the same time. Every problem includes a worked solution and commentary on trade-offs.

Sample Problems

Running top-N per group

-- Top 3 customers by revenue per region
SELECT * FROM (
    SELECT region, customer_id,
           SUM(order_value)                                   AS revenue,
           RANK() OVER (PARTITION BY region ORDER BY SUM(order_value) DESC) AS rk
    FROM   orders
    GROUP BY region, customer_id
) t WHERE rk <= 3;

SCD Type 2 merge

MERGE INTO dim_customer tgt
USING stage_customer src ON tgt.customer_id = src.customer_id AND tgt.is_current = 1
WHEN MATCHED AND tgt.address != src.address THEN
    UPDATE SET tgt.effective_end = CURRENT_DATE - 1, tgt.is_current = 0
WHEN NOT MATCHED THEN
    INSERT (customer_id, address, effective_start, effective_end, is_current)
    VALUES (src.customer_id, src.address, CURRENT_DATE, '9999-12-31', 1);
