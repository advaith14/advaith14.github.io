Data Engineering Framework

Python PySpark Databricks Azure Snowflake Delta Lake

A reusable PySpark library built to standardise how data pipelines are written across a team — covering multi-source ingestion, Informatica-style transformations, regression testing, and Unity Catalog write-back.

Overview

Data engineering teams often end up with pipelines that work but don't scale — each one written slightly differently, with different patterns for joining, testing, and writing data. This framework was built to solve that. It gives a team a single set of well-tested, well-documented functions that cover the full lifecycle from connection to write-back, so pipelines become assembly work rather than greenfield engineering every time.

⚡

Multi-Source Ingestion

Unified connector pattern for JDBC (SQL Server, Oracle), Azure Blob, Snowflake, Salesforce, and REST APIs.

🔄

Transformation Library

Informatica-inspired functions: router, joiner, checksum, SCD flag generation, lookup — all in PySpark.

🧪

Regression Testing

Schema comparison, row-level hash diffs, cell-by-cell mismatch reporting — catches data drift before it reaches prod.

🏗️

Write-Back Patterns

Delta Lake merge/upsert with auto-generated merge conditions, table swap, and Unity Catalog schema-qualified writes.

Key Capabilities

Multi-Source Ingestion

  • On-Prem JDBC — SQL Server and Oracle via configurable named connection profiles
  • Azure Blob Storage — CSV, JSON, text, and Delta formats with container abstraction
  • Snowflake — Read/write via the Spark-Snowflake connector, RSA key authentication
  • Salesforce — Bulk and standard API for insert, update, and upsert operations
  • REST APIs — Paginated fetch with OAuth2 token refresh and catalog upsert

Transformation Utilities

Inspired by the transformations in visual ETL tools like Informatica PowerCenter — so that teams moving off legacy ETL have familiar concepts with Spark performance:

  • infa_router — splits a DataFrame into multiple outputs based on filter conditions
  • infa_joiner — wraps Spark join with consistent defaults and suffix handling
  • md5_checksum — generates MD5 hashes across configurable column lists for change detection
  • generate_insert_update_delete_flags — SCD-style IUD flag generation from a staged join
  • lookup_dataframe — left join lookup with configurable return columns and key mapping

Regression Testing

  • compare_schemas — validates column names and data types between two DataFrames
  • hash_comp — row-level MD5 comparison to surface data drift between pipeline runs
  • compare_dataframes — cell-by-cell diff with full mismatch reporting
  • check_for_special_characters — flags columns containing unexpected or breaking characters

A taste of the API

# SCD-style IUD flag generation
df_joined = infa_joiner(df_stage, df_target, "left", ["customer_id"])
df_flagged = generate_insert_update_delete_flags(df_joined, {
    "insert_flag": "customer_id_right IS NULL",
    "update_flag": "md5_stage != md5_target",
})
